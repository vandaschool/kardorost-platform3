# کاردرست — تحویل چهارم: رزرو و هماهنگی مشاوره

این پروژه بازسازی تازه بر پایه Laravel 13، PHP 8.4، PostgreSQL و Vue 3/Inertia 3 است. این نسخه **بنیان قابل اجرای پلتفرم** است و نسخه کامل همه ماژول‌ها محسوب نمی‌شود. داده، حساب، رمز، توکن یا تنظیمات سرویس نسخه‌های قبلی منتقل نشده‌اند.

## قابلیت‌های پیاده‌شده

- ثبت‌نام با موبایل، کد تأیید کوتاه‌عمر، تعیین رمز و ورود با رمز ثابت.
- بازیابی رمز با پیامک و تغییر رمز با تأیید رمز قبلی؛ محدودیت درخواست و تلاش ناموفق.
- چهار نقش دانشجو، مربی، مدیر سازمان و ادمین، نقش‌های همزمان و تغییر پنل.
- جلوگیری از استفاده از حساب غیرفعال و اعمال دسترسی سمت سرور.
- پوسته شیشه‌ای فارسی، راست‌چین، موبایل و روشن/تیره؛ فونت‌ها و لوگوی نسخه جدید.
- خانه دانشجو با آمار واقعی حساب و حالت‌های خالی؛ بدون آمار نمونه.
- ساخت دوره و نوبت اول با ظرفیت، مرحله، مبلغ، شیوه ارائه و وضعیت انتشار.
- نمایش دوره، جست‌وجو، ثبت‌نام رایگان، رزرو ظرفیت پولی برای ۱۵ دقیقه و صفحه ثبت‌نام‌های من.
- کد درخواست و تأیید زیبال با کنترل مبلغ و شناسه سفارش، جلوگیری از پردازش تکراری و حفظ مبلغ زمان ثبت‌نام.
- پرداخت دیرهنگامِ فاقد ظرفیت یا پرداخت اضافه به وضعیت نیازمند بررسی منتقل می‌شود؛ فعال‌سازی بی‌ظرفیت انجام نمی‌شود.
- مدیریت نقش و فعالیت حساب‌ها، تخصیص مربی و نمایش فقط دوره‌های تخصیص‌یافته در پنل مربی.
- ایجاد دانشگاه/شرکت، تعیین مدیر از کاربران تأییدشده، افزودن اعضای ثبت‌شده و گزارش ثبت‌نام فردی در محدوده همان سازمان.
- ثبت سابقه عملیات حساب، دسترسی، دوره، سازمان و پرداخت.
- فضای آموزش دوره: سرفصل، درس متنی و ویدیو، زمان انتشار، ذخیره محل توقف و تکمیل خوداظهاری درس.
- پخش از لینک MP4، HLS و نمایشگر آروان؛ بارگذاری پخش‌کننده HLS فقط هنگام نیاز.
- تعریف کلاس گوگل میت، اسکای‌روم یا زوم برای هر نوبت؛ ورود در بازه جلسه و نمایش لینک ضبط پس از پایان آن.
- ثبت حضور دستی توسط مربی تخصیص‌یافته یا ادمین؛ کلیک لینک کلاس به‌تنهایی حضور ثبت نمی‌کند.
- تمرین متنی و فایل خصوصی، نسخه‌های پاسخ، امتیاز، درخواست اصلاح، بازخورد و تاریخچه ویرایش بازخورد.
- اعلان داخلی ماندگار بازخورد به دانشجو، فهرست اعلان‌ها و علامت خوانده‌شدن در محدوده حساب خودش.
- گزارش پیشرفت، حضور، پاسخ‌ها، فایل‌ها و نمره برای مدیر سازمان منتخب و اعضای همان مجموعه.

- صورتحساب شخصی، مانده و سررسید اقساط، انتخاب پرداخت کامل یا اقساط پیش از رزرو.
- برنامه اقساط مستقل هر نوبت با حفظ نسخه مالی ثبت‌نام‌های قبلی و جلوگیری از بازنویسی فرم قدیمی ادمین.
- ارسال خصوصی رسید کارت‌به‌کارت، جلوگیری از استفاده تکراری رسید و بررسی مستقل مبلغ توسط ادمین.
- کارتابل رسیدها، بدهی‌ها و پرداخت‌های نیازمند بررسی؛ کنترل ظرفیت هنگام تخصیص وجه.
- انتخاب تاریخ شمسی و تبدیل یک‌باره مبلغ نمایشی تومان به ریال داخلی.

- انتشار زمان مشاوره رایگان با تأیید صریح مربی یا ادمین، تاریخ شمسی و ساعت تهران.
- رزرو مستقیم، درخواست هماهنگی انسانی و تعیین زمان توافق‌شده از کارتابل ادمین.
- جلوگیری از تداخل زمان‌های مربی و رزروهای دانشجو، لغو پیش از شروع و حفظ تاریخچه.
- ثبت برگزاری یا عدم حضور پس از پایان، خلاصه مشترک، اعلان داخلی و ورود محدود به بازه جلسه.

## هنوز پیاده نشده

- انجمن، نظرسنجی و گواهی پایان دوره.
- اجرای آزمون‌ها، امتیازدهی نسخه‌دار، گزارش‌های شغلی، AI و ابزار رزومه.
- پرداخت مشاوره، سهمیه جلسات پکیج، تعرفه، یادآوری پیامکی و تسویه مربیان.
- تخفیف، بازپرداخت و تسویه مالی مربیان.
- مجوز سازمانی، ظرفیت صندلی، ثبت‌نام گروهی و خروجی گزارش‌ها.
- CMS و مقاله‌ها، توسعه سایر اعلان‌ها و پیام‌رسانی، پشتیبانی، گیمیفیکیشن و تحلیل‌ها.
- مدیریت جزئی دسترسی ادمین محدود و توسعه کامل همه زیرصفحه‌های مدیریت.
- انتقال و اتصال صفحه عمومی v16؛ مسیر ریشه این تحویل به ورود/پنل هدایت می‌شود.

بخش خودشناسی در ناوبری دانشجو فعلاً غیرفعال و با برچسب «به‌زودی» مشخص است. بخش مشاوره فعال شده است. ورود به درس، کلاس و تمرین از دکمه «ادامه یادگیری» همان دوره انجام می‌شود.

## اجرای توسعه

نیازها: PHP 8.4 با PDO، pdo_sqlite یا pdo_pgsql، mbstring، xml، dom، curl، fileinfo، OpenSSL؛ Composer 2؛ Node.js 24 و npm.

```bash
cp .env.local.example .env
composer install
php artisan key:generate
php -r "file_exists('database/database.sqlite') || touch('database/database.sqlite');"
php artisan migrate
npm ci
npm run build
php artisan serve
```

سپس آدرس خروجی `artisan serve` را باز کنید. برای توسعه فرانت‌اند، `npm run dev` را در ترمینال دوم اجرا کنید.

در محیط **local**، پیامک با `SMS_DRIVER=log` فقط در `storage/logs/laravel.log` ثبت می‌شود. این حالت پیامک واقعی نمی‌فرستد و در production قابل استفاده نیست. کد از پاسخ HTTP یا رابط کاربری افشا نمی‌شود؛ فقط توسعه‌دهنده محلی لاگ را می‌خواند.

دیتابیس پیش‌فرض توسعه SQLite است؛ در آزمون یکپارچه از PostgreSQL 17 هم استفاده شده است. هیچ حساب عمومی یا رمز پیش‌فرضی ساخته نمی‌شود. `db:seed` هم حساب نمونه نمی‌سازد.

## اولین ادمین

ابتدا با مسیر ثبت‌نام، موبایل را تأیید و حساب را بسازید. سپس از کنسول سرور:

```bash
php artisan platform:grant-role 09123456789 admin
```

این دستور فقط به حساب موجود و تأییدشده نقش می‌دهد. شماره مثال را با شماره حساب خود جایگزین کنید. ادمین از پنل می‌تواند نقش مربی/مدیر سازمان/ادمین را به کاربران بدهد؛ نقش مدیر سازمان به تنهایی دسترسی به سازمان خاصی ایجاد نمی‌کند و عضویت مدیریتی آن مجموعه نیز لازم است.

## اتصال سرویس واقعی

- فایل `.env.example` نمونه production با PostgreSQL و سرویس‌های غیرفعال است؛ مقادیر واقعی را فقط در محیط امن سرور وارد کنید.
- پیامک: در این تحویل آداپتور خدماتی کاوه‌نگار آماده شده است. `SMS_DRIVER=kavenegar`، کلید و قالب تأییدشده لازم‌اند. انتخاب کاوه‌نگار یک انتخاب پیاده‌سازی قابل تغییر است، نه الزام محصول.
- زیبال: `ZIBAL_ENABLED=true` و مرچنت معتبر؛ مبلغ داخلی ریال و مبلغ رابط تومان است. `APP_URL` باید دامنه صحیح HTTPS باشد تا callback معتبر ساخته شود.
- درخواست و verify زیبال با پاسخ شبیه‌سازی‌شده در آزمون‌ها بررسی شده‌اند؛ پرداخت زنده یا سازگاری پاسخ حساب تجاری شما هنوز آزموده نشده است. درگاه تا انجام بررسی محیط تست واقعی نباید به عنوان آماده بهره‌برداری معرفی شود.
- نتیجه بازگشت درگاه به‌تنهایی پرداخت را فعال نمی‌کند. در نبود سرویس یا خطای تأیید، ثبت‌نام پولی فعال نمی‌شود.
- در استقرار عمومی، HTTPS و کوکی secure فعال و APP_DEBUG خاموش باشند. پشتیبان‌گیری و مانیتورینگ قبل از بهره‌برداری عملیاتی لازم‌اند.

## کار با فضای آموزشی

۱. ادمین یا مربی تخصیص‌یافته از فهرست دوره‌های خودش وارد «مدیریت آموزش» می‌شود.
۲. سرفصل می‌سازد و متن درس یا لینک ویدیو را وارد می‌کند. پیش‌نویس و درس آینده، متن یا لینک قابل استفاده برای دانشجو افشا نمی‌کند.
۳. درس‌ها در سطح دوره مشترک‌اند؛ جلسه، تمرین، حضور و پاسخ‌ها به نوبت انتخاب‌شده تعلق دارند.
۴. دانشجو با ثبت‌نام فعال، «ادامه یادگیری» را باز می‌کند؛ محل توقف ویدیوهای مستقیم ذخیره می‌شود. برای نمایشگر iframe آروان، ثبت موقعیت از داخل پخش‌کننده پیاده نشده است.
۵. تکمیل درس با دکمه خود دانشجو ثبت می‌شود؛ زمان ذخیره‌شده ویدیو، مدرک مشاهده کامل و مبنای صدور گواهی خودکار نیست.
۶. پاسخ تمرین می‌تواند متن یا فایل PDF، تصویر JPEG/PNG یا DOCX تا ۱۰ مگابایت باشد. فایل‌ها در دیسک خصوصی `learning`، بیرون از وب‌روت و بدون URL عمومی ذخیره می‌شوند.
۷. هر ارسال یک نسخه جدید می‌سازد؛ فرم قدیمی پاسخ تازه‌تر را بازنویسی نمی‌کند. پاسخ بررسی‌شده فقط با درخواست اصلاح مربی دوباره قابل ارسال است.
۸. هر ویرایش بازخورد نیز یک رکورد تاریخچه جدید دارد. مربی پاسخ‌های قبلی را می‌بیند و مدیر سازمان به گزارش‌ها و فایل‌های اعضای سازمان منتخب خود دسترسی دارد.
۹. موعد پیشنهادی تمرین به‌تنهایی ارسال را نمی‌بندد؛ زمان بستن ارسال اختیاری است. سقف نمره پس از دریافت اولین پاسخ ثابت می‌ماند تا نمره‌ها تغییر معنا ندهند.
۱۰. لینک جلسه از ۱۵ دقیقه پیش از شروع تا پایان فعال است. حضور صرفاً با ثبت مربی یا ادمین تعیین می‌شود.

### محدودیت اتصال ویدیو و کلاس

این تحویل آپلود مستقیم به API آروان یا ساخت خودکار جلسه در Google Meet/Skyroom/Zoom ندارد؛ لینک‌های موجود در فضای مدیریت ثبت می‌شوند. ویدیوی واقعی حساب آروان هنوز آزمایش نشده است. تنظیم CORS، مجوز پخش، دامنه سفارشی، طول عمر لینک و احتمالا لینک امضاشده باید با حساب واقعی آروان بررسی شوند. داشتن لینک برای کاربر دارای دسترسی به معنی تضمین جلوگیری از کپی یا دانلود نیست.

دامنه‌های مجاز نمایشگر iframe آروان از `ARVAN_EMBED_HOSTS` و دامنه‌های اسکای‌روم از `SKYROOM_HOSTS` خوانده می‌شوند. لینک‌ها باید HTTPS باشند؛ نمایشگر iframe از دامنه دلخواه پذیرفته نمی‌شود. بررسی URL ساختاری است و موجودبودن و قابلیت پخش لینک را اثبات نمی‌کند.

برای فایل ۱۰ مگابایتی، تنظیمات سرور نیز باید کافی باشند؛ پیشنهاد: `upload_max_filesize=12M`، `post_max_size=16M` و در Nginx مقدار `client_max_body_size 16m`. فایل‌های خصوصی `storage/app/learning-private` باید همراه دیتابیس backup شوند و هرگز با symlink عمومی منتشر نشوند.

## کار با پرداخت و اقساط

ادمین در تنظیم مالی هر نوبت، پرداخت دستی و برنامه ۲ تا ۱۲ قسط را تعیین می‌کند. مجموع اقساط باید دقیقاً برابر مبلغ دوره باشد. قسط اول هنگام رزرو سررسید می‌شود؛ تأیید و تخصیص آن ثبت‌نام را فعال می‌کند. ویرایش برنامه نوبت، صورتحساب دانشجوی قبلی را تغییر نمی‌دهد.

برای کارت‌به‌کارت، `MANUAL_PAYMENT_DESTINATION` و `MANUAL_PAYMENT_HOLDER` را تنظیم کنید. مقصد باید شماره حساب/کارت عددی ۸ تا ۳۰ رقمی یا شبای IR با ۲۴ رقم باشد. `RECEIPT_REVIEW_HOLD_HOURS` زمان حفظ رزرو اولیه پس از ارسال رسید است (پیش‌فرض ۲۴ ساعت). فایل PDF/JPG/PNG تا ۵ مگابایت در `storage/app/receipts-private` ذخیره می‌شود؛ این مسیر باید خصوصی و همراه دیتابیس پشتیبان‌گیری شود.

ارسال عکس رسید به معنی پرداخت نیست. ادمین باید واریز را مستقلاً در گردش حساب بررسی و مبلغ تأییدشده را وارد کند. تأیید رسید فاقد ظرفیت، وجه را برای بررسی نگه می‌دارد و صندلی اضافی ایجاد نمی‌کند. بازیابی تخصیص از کارتابل مالی همچنان مشروط به صحت مبلغ، صورتحساب و ظرفیت است. بازپرداخت خودکار و اتصال API گردش حساب پیاده نشده‌اند.

بدهی فقط برای اقساط جاری ثبت‌نام فعال محاسبه می‌شود؛ رزرو رهاشده بدهی تحصیلی نیست. جریمه و قطع خودکار دسترسی به درس بابت تأخیر فعال نشده‌اند. تصاویر رسید فقط برای صاحب حساب و ادمین قابل دریافت‌اند؛ مدیر سازمان دسترسی بانکی شخصی اعضا را به ارث نمی‌برد.

## کار با مشاوره

دانشجو از «مشاوره» زمان رایگان را مستقیماً رزرو می‌کند یا موضوع و ساعت‌های مناسب را برای هماهنگی می‌فرستد. هر دانشجو حداکثر یک درخواست هماهنگی باز دارد. ادمین پس از هماهنگی بیرون از سامانه، از همین کارتابل زمان آزاد را تعیین می‌کند؛ درخواست تا رزرو موفق باز می‌ماند. نتیجه در اعلان داخلی و صفحه مشاوره دیده می‌شود. تماس انسانی یا پیامک خودکار ارسال نمی‌شود.

مربی از منوی مشاوره خودش زمان ۱۵ تا ۱۸۰ دقیقه‌ای تا یک سال آینده منتشر می‌کند. انتشار مستلزم تأیید صریح رایگان‌بودن است؛ هیچ تعرفه یا سهمیه پکیجی از نسخه قدیم به صورت ضمنی اعمال نشده است. پرداخت پولی مشاوره هنوز پیاده نشده و این بخش در این تحویل فقط برای جلسه رایگان است.

تداخل زمان‌های مربی حتی در زمان پنهان مجاز نیست. زمان‌ها قابل جابه‌جایی نیستند؛ برای تغییر زمان رزروشده، ابتدا جلسه آینده با دلیل لغو و سپس زمان تازه رزرو می‌شود. لغو فقط پیش از شروع ممکن است و تاریخچه را حذف نمی‌کند. ادمین و مربی پس از پایان بازه، «برگزار شد» یا «عدم حضور» را ثبت می‌کنند؛ خلاصه درج‌شده برای دانشجو نیز قابل مشاهده است و محل یادداشت خصوصی مربی نیست.

لینک معتبر Meet/Skyroom/Zoom از ۱۵ دقیقه قبل تا پایان جلسه در اختیار شرکت‌کنندگان قرار می‌گیرد. سایر دانشجویان، مربیان دیگر و مدیر سازمان به موضوع، خلاصه و لینک جلسه دسترسی ندارند؛ ادمین پلتفرم دسترسی عملیاتی دارد. کلیک ورود اثبات حضور نیست و API ساخت جلسه یا دریافت خودکار حضور وجود ندارد. زمان ذخیره‌شده با منطقه زمانی برنامه Asia/Tehran و قرارداد موجود پروژه هماهنگ است؛ تغییر منطقه زمانی سرور برنامه نیازمند بررسی داده‌های زمانی است.


نتیجه این تحویل: ۱۲۵ آزمون و ۸۰۳ assertion روی PostgreSQL پاس شده‌اند. هشت آزمون همزمانی با پردازش‌های مستقل مخصوص PostgreSQL هستند. روی SQLite، ۱۱۷ آزمون پاس و هشت آزمون skip شده‌اند (۷۶۲ assertion). شش آزمون فرانت‌اند برای تاریخ و مبلغ و ساخت production نیز موفق بودند.

سناریوها شامل ثبت‌نام و بازیابی، حد تلاش و انقضای کد، جلوگیری از افزایش نقش توسط دانشجو، جداسازی سازمان‌ها، غیرفعال‌سازی نشست، CSRF، ظرفیت، مبلغ سفارش، تکرار callback، پرداخت دیرهنگام و رقابت همزمان آخرین صندلی هستند. همچنین دسترسی کلاس، پنهان‌ماندن پیش‌نویس و محتوای آینده، تداخل نوبت‌ها، خصوصی‌بودن فایل، محدودیت بارگذاری، نسخه‌های پاسخ، رقابت ارسال همزمان، تاریخچه و نمره صفر، سقف نمره ثابت و محدودیت دسترسی سازمان بررسی شده‌اند.

مسیر رزرو و درخواست هماهنگی دانشجو، جداسازی درخواست‌ها از مربی و نمایش صف ادمین در Chromium بررسی شد. چیدمان RTL در عرض ۳۹۰ و ۱۴۴۰ پیکسل نیز مشاهده شد؛ در این مسیر خطای JavaScript ثبت نشد. این بررسی محدود به مسیر مشاوره است و تأیید همه صفحات یا مرورگرها نیست. آزمون مرورگر در `tests/browser/consultations.mjs` روی داده و سرور محلی مستقل، با Chromium CDP پورت ۹۲۲۲ و متغیرهای BROWSER_BASE_URL، BROWSER_PASSWORD و BROWSER_STUDENT_PHONE/BROWSER_COACH_PHONE/BROWSER_ADMIN_PHONE اجرا می‌شود. فقط localhost مجاز است؛ حساب‌ها و یک زمان آزاد مربی باید در دیتابیس آزمایشی آماده باشند.

## استقرار

این برنامه PHP/PostgreSQL است و برای استقرار روی سرور Laravel آماده‌سازی شده؛ روی میزبانی استاتیک یا Cloudflare Worker اجرا نمی‌شود. در این تحویل روی دامنه عمومی یا سرویس production مستقر نشده است.

ریشه وب‌سرور باید `public/` باشد؛ فقط `storage/` و `bootstrap/cache/` قابل نوشتن توسط پردازش وب باشند. نصب وابستگی production با `composer install --no-dev --optimize-autoloader`، ساخت فرانت با `npm ci && npm run build` و migration با `php artisan migrate --force` انجام می‌شود. قبل از migration عملیاتی backup گرفته شود. هیچ فایل `.env`، دیتابیس توسعه یا لاگ نباید در وب‌روت قرار بگیرد.
